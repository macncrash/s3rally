# S3-32 and S3-64

The 32-bit successor to the S3-16, in the mould of the mid-90s polygon
consoles. It runs on the same board as the 16-bit machine: the same window, pad,
controller mapping, save storage, multi-cart menu and sound chip. Only the video
hardware is new.

## One board, many consoles

The goal is a single engine that can host many console designs, with the same
controls and menus throughout:

```
 host board (src/console/system)   window · CRT filter · pad and controller map · audio device
                                    saves · screenshots · boot ROM · multi-cart menu · network link
      │
      ├── S3-16 core   VDP (tiles, scaled sprites, road generator) + APU (FM, PSG, PCM)
      ├── S3-32 core   GPU (polygons, ordering table) + the same APU (the 32-bit machine keeps the sound chip)
      └── S3-64 core   the same GPU as model S3_64: depth buffer, perspective-correct, filtered, 640×480
```

A cartridge that brings its own video hardware sets `Cart::video()`. The board
then presents that frame (any size, scaled to 4:3) instead of the 16-bit VDP. It
keeps the same input and the same menus, and ESC on a title screen still returns
to the multi-cart. Adding another console later means adding another core next
to these two. The board, the controls and the menus don't change.

## Video (`src/g32/gpu.h`)

| | |
|---|---|
| Resolution | 320×240 at 60 Hz, shown at 4:3 |
| Colour | 15-bit (32,768 colours) with 4×4 ordered dithering of shaded pixels |
| Texture RAM | 2 MB of 16-bit texels (5-5-5 plus a transparency bit), textures up to 256×256 that tile |
| Primitives | triangles and quads: flat or Gouraud shaded, textured (affine: textures swim a little, as they did) or not; screen-space sprites |
| Blending | opaque, half-transparent (average) and additive |
| Depth | no depth buffer. The GPU keeps an ordering table of 4096 depth buckets and draws back to front, as the era's machines did |
| Depth cue | per-vertex fog towards a fog colour register |
| Budget | about 4,000 triangles per frame |

## S3-64 (`g32::Model::S3_64`)

The next board is a revision of the same GPU, not a new one. It takes the same
command stream, so a cartridge becomes a 64-bit cartridge by constructing its
GPU as `GPU(Model::S3_64)`. The cartridge keeps drawing in 320×240 coordinates
and the 64 scales them up. It fixes what the 32-bit generation faked:

| | S3-32 | S3-64 |
|---|---|---|
| Resolution | 320×240 | 640×480 |
| Colour | 15-bit, dithered | 24-bit |
| Visibility | ordering table only | per-pixel depth buffer (1/z); the ordering table remains for blended polygons and the HUD |
| Texturing | affine (swims) | perspective-correct (u/z, v/z, 1/z, one divide per pixel) |
| Filtering | nearest texel | bilinear, with mipmaps for repeating textures (level chosen per row from the screen-space texture gradient) |
| Texture RAM | 2 MB | 8 MB, mip chains included |
| Budget | ~4,000 triangles | ~16,000 triangles |
| Pipelines | one | up to 8, each drawing a band of the screen (single in the browser build) |

Draw order on the 64: opaque 3D polygons go **nearest first**, so the depth
test turns hidden pixels away before any texturing is done. Blended polygons
and the HUD then follow in ordering-table order. `--sim --cart rally64` drives
every stage and reports the median frame time while driving.

## Geometry unit (`src/g32/gte.h`)

This is a small fixed-function maths unit. It has vector and 3×3 matrix
arithmetic, a camera (position, yaw, pitch, roll, focal length), perspective
projection with a depth value for the ordering table, and near-plane clipping so
polygons that pass the camera are cut rather than dropped.

## Sound

It uses the S3-16 APU unchanged: 9 FM channels, PSG, noise and 4 PCM
channels with stereo echo. The radio, engine and co-driver work on both machines.

## Roadmap

1. **Done:** the board accepts cartridges with their own video; GPU, geometry
   unit and ordering table; **(3) RALLY 32**, a first cartridge that drives the
   rally's stages, car physics and art in real 3D.
2. A 24-voice sampler with ADSR and reverb (a SPU) alongside the APU.
3. **Done (preview):** the S3-64: depth buffer, perspective-correct and filtered textures, 640×480 24-bit, parallel pipelines; **(3) RALLY 64**.
4. The multi-cart grows into a **console menu**: pick the machine, then the
   game, with the same keys everywhere.
5. S3-64 part 2: hardware transform and lighting (meshes and matrices submitted to the GPU, per-vertex directional light), environment-mapped car paint, a higher-poly car, real trees up close.
6. A third core (an 8-bit handheld) to prove the board really is general.
